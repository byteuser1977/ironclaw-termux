# IronClaw 概要设计文档

## 1. 项目概述

### 1.1 项目名称
IronClaw - 安全的个人AI助手框架

### 1.2 项目描述
IronClaw是一个基于Rust构建的安全个人AI助手框架，专注于数据隐私保护和动态能力扩展。系统采用多层安全架构，支持多种交互通道，提供持久化记忆和自动化任务执行能力。

### 1.3 设计理念
- **数据所有权**: 所有数据本地存储，加密保护，永不离开用户控制
- **透明设计**: 开源可审计，无隐藏遥测或数据收集
- **动态扩展**: 可动态构建新工具，无需等待供应商更新
- **深度防御**: 多层安全防护，防止提示注入和数据泄露

### 1.4 技术栈
- **编程语言**: Rust 1.92+
- **异步运行时**: Tokio
- **数据库**: PostgreSQL 15+ (默认) / libSQL (嵌入式)
- **向量扩展**: pgvector
- **沙箱**: WebAssembly (WASM) + Docker
- **LLM集成**: 多提供商支持 (NEAR AI, OpenAI, Anthropic, Ollama等)

### 2.2 核心组件

| 组件 | 职责 | 关键特性 |
|------|------|----------|
| **Agent Loop** | 主消息处理和任务协调 | 意图识别、任务调度、并行执行 |
| **Router** | 用户意图分类 | 命令/查询/任务路由 |
| **Scheduler** | 并行任务调度 | 优先级队列、资源管理 |
| **Worker** | 任务执行 | LLM推理、工具调用、错误恢复 |
| **Safety Layer** | 安全防护 | 提示注入防御、内容净化、凭证保护 |
| **Tool Registry** | 工具管理 | 内置工具、MCP集成、WASM动态工具 |
| **Workspace** | 持久化记忆 | 混合搜索、文档管理、向量嵌入 |
| **Sandbox** | 安全执行 | WASM沙箱、Docker容器、网络代理 |
| **Orchestrator** | 容器编排 | 生命周期管理、LLM代理、认证 |
| **Routine Engine** | 自动化任务 | Cron调度、事件触发、Webhook处理 |

## 3. 核心功能

### 3.1 多通道交互
- **CLI**: 交互式命令行界面
- **HTTP**: Webhook和REST API
- **WASM Channels**: Telegram、Slack、WhatsApp、Discord
- **Web Gateway**: 浏览器UI，支持SSE/WebSocket实时流

### 3.2 安全沙箱执行
- **WASM Sandbox**: WebAssembly隔离执行，基于能力的权限控制
- **Docker Sandbox**: 容器化执行，完整的操作系统隔离
- **网络代理**: 域名白名单、凭证注入、泄露检测
- **资源限制**: 内存、CPU、执行时间约束

### 3.3 工具系统
- **内置工具**: 文件操作、网络请求、记忆管理等
- **MCP协议**: 连接Model Context Protocol服务器
- **动态构建**: 描述需求，自动构建WASM工具
- **插件架构**: 热插拔WASM工具和通道

### 3.4 持久化记忆
- **混合搜索**: 全文搜索 + 向量搜索 (Reciprocal Rank Fusion)
- **工作空间文件系统**: 灵活的路径存储
- **身份文件**: 跨会话保持一致的性格和偏好
- **上下文压缩**: 长对话的智能压缩

### 3.5 自动化任务
- **Cron调度**: 定时任务执行
- **事件触发**: 基于系统事件的响应
- **Webhook处理**: 外部事件集成
- **心跳系统**: 主动后台监控和维护

### 3.6 多LLM支持
- **NEAR AI**: 默认提供商，支持OAuth和API密钥
- **OpenAI兼容**: OpenRouter、Together AI、Fireworks AI等
- **Anthropic**: 直接API访问，支持提示缓存
- **Ollama**: 本地模型推理
- **AWS Bedrock**: 原生Converse API
- **智能路由**: 廉价/主模型分流、故障转移、熔断器

### 4.2 安全特性

| 安全层 | 机制 | 保护目标 |
|--------|------|----------|
| **输入层** | 格式验证、长度限制 | 防止缓冲区溢出、资源耗尽 |
| **净化层** | 模式检测、内容转义 | 防止提示注入 |
| **策略层** | 规则引擎、动作决策 | 强制执行安全策略 |
| **执行层** | WASM/Docker沙箱、网络代理 | 隔离不信任代码 |
| **凭证层** | 密钥注入、泄露检测 | 防止凭证泄露 |
| **输出层** | 内容过滤、XML包装 | 防止数据泄露 |

## 5. 数据流

### 5.1 消息处理流程

```
用户消息 → 通道接收 → 消息路由 → 意图分类
    │
    ├─ 命令 → 直接执行 → 返回结果
    │
    ├─ 查询 → LLM推理 → 返回响应
    │
    └─ 任务 → 创建Job → 调度器 → Worker
                    │
                    ├─ LLM推理
                    ├─ 工具调用 → 沙箱执行 → 结果净化
                    └─ 迭代循环 → 完成任务
```

### 5.2 工具执行流程

```
LLM决策调用工具
    │
    ▼
参数验证
    │
    ▼
安全检查 (权限、白名单)
    │
    ▼
凭证注入 (代理层)
    │
    ▼
沙箱执行 (WASM/Docker)
    │
    ▼
输出收集
    │
    ▼
泄露扫描
    │
    ▼
内容净化
    │
    ▼
返回LLM
```
